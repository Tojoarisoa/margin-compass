## 2. Work breakdown

### M2-01 Full simulator + chunked backfill
1. **Tenants and contracts** (spec §2, §5):
   - 400 tenants across 5 segments × 3 plans, with log-normal ARR rescaled to $24.0M;
   - contract clauses: unlimited AI, approved-model list, data residency, SLAs, discounts;
   - SCD2 history for plan changes;
   - growth of +2% tenants a month, with onboarding waves in Jan and Sep.
2. **Features and models** (spec §3–§4):
   - F0–F4 with their token distributions;
   - tiers small / mid / frontier plus `emb-1`;
   - an effective-dated catalog including the `b-mid` −40% cut on 2026-03-01;
   - cached and batch pricing.
3. **Telemetry grain** (spec §12 item 2): Enterprise hourly, others daily, plus a 1% raw request sample with trace IDs.
4. **Outcomes** (spec §12 item 3a):
   - tenant × day aggregates;
   - a 10% per-ticket sample;
   - every labeled safety event;
   - F0 flags drawn from the tier's recall (spec §4).
5. **Shared infrastructure** (new, for S2): a FOCUS 1.2-shaped daily cost export for BoonCore's own platform. It covers compute for F2 agents, vector storage and queries for F3, egress, observability, and third-party APIs, with `x-feature` and `x-env` tags, and includes PT-12 (an idle staging GPU and an oversized vector tier).
6. **Patterns** PT-01…PT-14:
   - each one writes `labels/patterns` with a computed `expected_impact_usd_per_day`;
   - PT-08 and PT-09 are constraint and proposal labels;
   - PT-14 emits renewal churn and downgrade events with their true probabilities (spec §9; the closed loop is M5).
7. **Determinism by chunk:**
   - every month's output depends only on `(seed, month, tenant)` through per-stream RNGs, so any month can be regenerated byte-identically, alone or as part of the full run;
   - tests check chunk-alone vs full-run equality and the §7.5 row budgets.
8. **Backfill in AWS:**
   - a Step Functions Map runs over the 18 months (simulate + ingest one month per Lambda run, at most 2 concurrent), then one dbt build, then train, embed, and publish;
   - about 60 state transitions per backfill; a nightly run adds one day.

### M2-02 FOCUS ingestion, allocation, cost-to-serve marts
1. **Silver:**
   - `stg_focus_*` for the simulated S2 export and the real S7 export (same FOCUS 1.2 contract);
   - telemetry priced against the effective-dated catalog, including cached and batch rates;
   - revenue daily-ized, including overage and discounts;
   - outcomes joined to telemetry by trace ID (sample only).
2. **Allocation rules** in `reference/allocation_rules.yml`, versioned and effective-dated (default rules in §4 D2). Untagged or unmatched cost goes to an explicit **unallocated** bucket.
3. **Gold:**
   - `fct_infra_cost_allocated` (day × tenant × feature × rule);
   - `fct_cost_to_serve` (day × tenant × feature, by component);
   - `fct_unit_cost` (day × feature × model);
   - `fct_quality` (including `safety_events_labeled/flagged` and `safety_event_recall`, recomputed from summed counts, never averaged);
   - `fct_tenant_margin` switches to fully loaded cost;
   - `dim_tenant` (SCD2), `dim_feature`, `dim_model_price`.
4. **Gates:**
   - cost preservation: allocated + unallocated = billed, to the cent, for LLM **and** infrastructure;
   - revenue preservation per invoice line and per period;
   - each gate keeps its break-on-purpose test.

### M2-03 Semantic metrics, contracts, scorecard, lineage
1. **One definition per metric** (see §4 D4): gross margin $ and %, cost per outcome, attribution coverage, unit cost, safety-event recall. The definitions are used by the dbt marts, the publish step, the agent tools, and the evaluations.
2. **Contracts** for every mart: owner, SLA, schema, tests, PII class, consumers; documented in `docs/data-contracts/gold-marts-m2.md`.
3. **Statistical checks:** volume and distribution drift per source. These warn, except the PT-13 seasonality guard, which must **not** alert.
4. **Scorecard and lineage** published to `publish/` for PG-8.

### M2-04 Dashboard + dogfood telemetry
1. **PG-1 complete:**
   - margin per feature;
   - cost per outcome;
   - unprofitable tenants and ARR at risk;
   - margin trend with the forecast band.

   ROI and "margin recovered" stay placeholders until M3/M5.
2. **PG-2 Cost-to-Serve Explorer:**
   - tenant × feature × model drill-down;
   - per-tenant margin waterfall;
   - margin-vs-usage scatter;
   - attribution coverage.

   It uses DuckDB-WASM on an exploration Parquet ≤ 5 MB. This includes the **ADR-009 spike**: an exact pinned version (never 1.29.2), self-hosted bundles, and range reads through CloudFront. If the spike fails, PG-2 falls back to pre-aggregated JSON.
3. **PG-8 tabs:**
   - *Pipeline & Data Health*: scorecard, lineage, freshness, run history;
   - *Platform FinOps*: the real AWS bill by lifecycle stage from S7 FOCUS, budget burn-down, and the platform's own cost per question.
4. **Dogfood telemetry (S7):**
   - the agent API's `gen_ai_call` log events (no content) are compacted nightly into `telemetry/` Parquet;
   - they're ingested as the demo tenant `mc-demo`;
   - they're shown on PG-8, kept separate from BoonCore's margin.
5. **Agents:**
   - AG-03 tools read fully loaded cost (`fct_cost_to_serve`) and the new marts;
   - the replay set grows from 5 to about 8 questions;
   - fixtures are re-recorded on Haiku 4.5 (≈ $0.05).

## 3. Sequencing (about 2 weeks at ~10 h/week)

1. **Spike first:**
   - generate 18 months at full volume locally;
   - time and measure `dbt build` in DuckDB;
   - run the same build in the Lambda container at 4 GB.

   This sets the chunking and memory before the rest is built. Stop and re-plan if the full build needs more than 6 GB or 10 minutes (§7.5).
2. M2-01 simulator (tenants → telemetry → outcomes → FOCUS → patterns), with tests per pattern.
3. M2-02 silver/gold + allocation + gates.
4. M2-03 metrics + contracts + scorecard.
5. AWS: Map-based backfill, one deploy (owner approval), then verify AWS gold = local gold.
6. M2-04 dashboard pages + S7 telemetry; re-record agent fixtures.
7. Exit check, then PLAN.md ticks and the Change Log.

Each step is its own PR, with CI green and the cost gate showing the delta.

## 6. Risks

| Risk | Mitigation |
| --- | --- |
| Full dbt build too big for one Lambda run | Spike first (§3 step 1); incremental models by month; split silver per chunk |
| Simulator too slow in pure Python | Vectorize per tenant × day with numpy; the chunk-equality test guards against regressions |
| Real FOCUS export still empty (runbook G5) | PG-8 FinOps shows "awaiting first export"; S7 ingestion handles empty partitions |
| DuckDB-WASM bundle size or range reads | ADR-009 fallback: pre-aggregated JSON for PG-2 |
| Allocation rules disputed | Rules are versioned data with an unallocated bucket; the dashboard shows rule and coverage |
