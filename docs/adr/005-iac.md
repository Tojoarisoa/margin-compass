# ADR-005: Infrastructure as code: AWS CDK in Python

- **Status:** Proposed
- **Date:** 2026-11-02
- **Related:** PLAN.md §16, §19.4 #2, AGENTS.md DoD

## Context

All infrastructure must be in IaC (Definition of Done). The owner chose the tool on 2026-11-02.

## Decision

**AWS CDK v2 in Python**, one app with stacks: foundation, data, ml, agents, web, observability. Every construct applies the mandatory tags (`project`, `env`, `stage`, `owner`, `cost-center`) through a CDK Aspect, and an Aspect test fails synthesis if a forbidden resource (§11.2) appears.

## Alternatives

| Option | Why not |
| --- | --- |
| CDK (TypeScript) | Second language in the repo |
| Terraform | Separate state backend to manage; less native for AWS-only |
| SAM | Weaker for non-Lambda resources |

## Consequences

- One language across infra, pipelines, ML, and agents.
- `cdk.context.json` is committed for deterministic synthesis.
- The forbidden-resource check runs in CI.

## Cost impact

$0 (CDK bootstrap creates an S3 bucket and ECR repo; storage is pennies).
